The child sandboxes itself and then execves our binary.</p><p>The sandbox is defined by two calls.</p><ul><li><code>prctl(PR_SET_NO_NEW_PRIVS, 1, ...)</code> lets a filter be installed without CAP_SYS_ADMIN and permanently blocks privilege gain through execve, so setuid binaries like <code>/readflag</code> are useless inside the child.</li><li>The filter is one instruction: <code>BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_USER_NOTIF)</code>. <code>BPF_RET | BPF_K</code> returns a constant, with no comparison on the syscall number, so <em>every</em> syscall the child makes is suspended and handed to userspace. <code>SECCOMP_FILTER_FLAG_NEW_LISTENER</code> makes <code>seccomp()</code> return the fd those notifications arrive on.</li></ul><p><code>close(listener)</code> is a handshake: as the first syscall under the filter it blocks until handled, so the child can&rsquo;t reach execve before the parent is ready.</p><p>The parent polls the child&rsquo;s memory with <code>process_vm_readv</code> for the fd number, steals the fd with <code>pidfd_open</code> + <code>pidfd_getfd</code>, runs <code>init_sup()</code> (registers fd 0-2 as real, everything else the child opens is virtual), and enters <code>supervisor()</code>.</p><h2 id=sandbox>Sandbox</h2><h3 id=architecture>Architecture</h3><p>In <code>supervisor()</code> we have the notification loop (select on both the listener and the pidfd, with req/resp alloca&rsquo;d on the supervisor&rsquo;s stack), a synthetic filesystem, proxied fds, and a syscall dispatcher.
